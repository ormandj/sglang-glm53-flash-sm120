Method
  1. Load real BF16 gate/up/down weights from the sealed teacher.
  2. Load the corresponding real uint8 packed MXFP4 values and E8M0 scales.
  3. Decompress with compressed-tensors and compare weights/output to BF16.
  4. Execute the packed values through FlashInfer's exact SM120
     MXFP8-activation x MXFP4-weight fused-MoE kernel after the same block-scale
     interleave used by SGLang.
  5. Repeat with the exact TP=2 intermediate split/reduce.
  6. Deliberately pass [gate; up] instead of FlashInfer's [up; gate] as a
     negative control.

Interpretation
  The actual published weights, packed-value nibble convention, E8M0 scale
  convention, [up; gate] post-load layout, standard clamped-SwiGLU parameters,
  FlashInfer SM120 kernel, and TP=2 intermediate split/reduce form a coherent
  numerical contract. The wrong-layout controls are sharply and consistently
  worse. These results rule out the principal MXFP4 runtime ABI hypothesis for
  the malformed full-model output.

  Direct uncalibrated MXFP4 introduces material one-layer output error versus
  BF16 (about 0.20 to 0.22 relative L2 in these random-activation samples).
  This diagnostic does not establish whether that error compounds enough over
  the complete 43-routed-layer model to explain the served-model failure. A
  full-model backend A/B and target-logit comparison remain required.

This is diagnostic evidence, not a served-model quality or performance claim.
