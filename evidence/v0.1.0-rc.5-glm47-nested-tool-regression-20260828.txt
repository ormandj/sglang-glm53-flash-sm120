The exact upstream GLM47 nested-object streaming regression was run inside a
temporary no-GPU source-inspection pod.  The tool schema contained a string
"kind" property and a nested object "payload" property.  Parser input was:

  <tool_call>acme<arg_key>kind</arg_key><arg_value>acme</arg_value><arg_key>payload</arg_key><arg_value>{"value": "hello"}</arg_value></tool_call>

Observed streamed name:
  acme
Observed concatenated arguments:
  {"kind": "acme", "payload": {"value": "hello"}
Expected arguments:
  {"kind": "acme", "payload": {"value": "hello"}}
Result:
  json.decoder.JSONDecodeError: Expecting ',' delimiter at column 47

The vendor parser conditionally appends the outer brace only when the most
recent argument text does not itself end in "}".  That condition confuses a
nested object's closing brace for the outer arguments object's closing brace.
The merged upstream fix tracks whether any outer parameter was emitted and
always closes that outer object.  It also resolves properties nested under a
top-level anyOf/oneOf/allOf schema.

This is a parser-only source regression, not a served-model quality or
performance result.  The diagnostic pod must not remain running.
